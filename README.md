## Working together

- `git pull` before you `git push`. If a push is rejected, someone else
  pushed first: pull, then push again.
- Commit every time something works, in small pieces. Commit messages
  describe what changed, not "stuff".
- One person owns each file. Overlapping edits are what cause conflicts.
- Never commit `.env` or any file holding an API key.
